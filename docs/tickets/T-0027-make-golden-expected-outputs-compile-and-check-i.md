Epic: T-0025.

## User story

As a maintainer, I want every golden `*.expected.cpp` to be valid C++
that GCC accepts against the real runtime. A golden fixture should prove
the lowering *works*, not only that the text is stable.

## Problem

Golden tests compare text only (`transpiler/tests/golden_tests.cpp`
`run_case`), so a fixture can pin output that does not compile. **Neither
existing fixture compiles today.** Reproduced on commit `2a7c317`, GCC 15.2:

```
$ g++ -std=c++20 -Wall -Wextra -fsyntax-only -Iruntime/include transpiler/tests/golden/nested_lambda.expected.cpp
nested_lambda.expected.cpp:8:29: error: 'fetch' was not declared in this scope
    8 |         co_return co_await (fetch(v));
$ g++ -std=c++20 -Wall -Wextra -fsyntax-only -Iruntime/include transpiler/tests/golden/simple_fn.expected.cpp
simple_fn.expected.cpp:5:13: error: awaitable type 'int' is not a structure
    5 |     int y = co_await (helper(x));
```

`simple_fn.async.cpp` awaits a plain `int helper(int)`, which is
meaningless in the output language. `nested_lambda.async.cpp` awaits an
undeclared `fetch`. Several ready tickets add fixtures in the same style
(T-0001 `braceless_return` uses an undeclared `fetch`). T-0004 already
asks for a one-off compile check of its fixture, so the need is
recognised but not generalised.

`-fsyntax-only` does catch coroutine-semantic errors, as the `awaitable
type 'int'` error above shows. It costs ~0.17 s per fixture.

## Scope

- In:
  - make the two existing fixtures self-contained;
  - add a `golden_compile` ctest plus the matching Makefile `test` step,
    which compiles every `transpiler/tests/golden/*.expected.cpp` with
    `-std=c++20 -fsyntax-only -I runtime/include`.
- Out:
  - Linking or running fixtures; examples already do that.
  - `-Wall -Wextra -Werror` on fixtures: fixtures may legitimately have
    unused parameters.
  - An opt-out mechanism. No planned fixture needs one. If one ever does,
    add an explicit per-fixture marker file then, with a reason.
- Touches:
  - `transpiler/tests/golden/{simple_fn,nested_lambda}.{async,expected}.cpp`
  - `cmake/check_golden_compile.cmake` (new)
  - `examples/CMakeLists.txt`
  - `Makefile`
  - README "Building this repo"

## Blueprint

1. **Fixtures.** Replace the inputs below and regenerate each expected file
   with `build/transpiler/asynctp <case>.async.cpp -o <case>.expected.cpp --no-line-directives`.
   The outputs below were generated by the architect with the current
   `asynctp`; both compile with `-Wall -Wextra`.

   `simple_fn.async.cpp` keeps a plain function whose `return` must pass
   through untouched, which was the original intent, and awaits an
   `async` wrapper:
   ```cpp
   int helper(int x) { return x + 1; }

   async int helper_async(int x) { return helper(x); }

   async int compute(int x) {
       int y = helper_async(x).await;
       return y * 2;
   }
   ```
   Expected:
   ```cpp
   #include <asyncrt/asyncrt.hpp>
   int helper(int x) { return x + 1; }

   ::asyncrt::Task<int> helper_async(int x) { co_return helper(x); }

   ::asyncrt::Task<int> compute(int x) {
       int y = co_await (helper_async(x));
       co_return y * 2;
   }
   ```
   `nested_lambda.async.cpp` gets one new first line and a blank line, and
   the rest is unchanged:
   ```cpp
   async int fetch(int v) { return v * 10; }

   async int run_all(int x) {
   ...(unchanged)...
   ```
   Expected: `#include <asyncrt/asyncrt.hpp>`, then
   `::asyncrt::Task<int> fetch(int v) { co_return v * 10; }`, a blank
   line, then the old expected body unchanged.

2. **`cmake/check_golden_compile.cmake`** (new, run with `cmake -P`).
   - Inputs: `-DCXX=`, `-DRUNTIME_INCLUDE=`, `-DGOLDEN_DIR=`.
   - Behaviour:
     - `file(GLOB …"${GOLDEN_DIR}/*.expected.cpp")`, sorted.
     - **An empty list is `FATAL_ERROR`** ("no golden fixtures found in
       …"), so a renamed directory cannot silently pass.
     - For each file, `execute_process(COMMAND ${CXX} -std=c++20
       -fsyntax-only -I${RUNTIME_INCLUDE} <file> RESULT_VARIABLE …
       ERROR_VARIABLE …)`.
     - Collect every failure, then one `message(FATAL_ERROR …)` that names
       each failing fixture followed by its compiler stderr.
     - On success print `golden_compile: N fixtures OK`.
   - The script itself knows nothing about either component; it is given
     paths. This follows T-0015's precedent for build-glue scripts in
     `cmake/` (`check_compile_commands.cmake`).

3. **`examples/CMakeLists.txt`**, inside the existing `if(BUILD_TESTING)`.
   `examples/` is the layer that may join transpiler fixtures and runtime
   headers.
   ```cmake
   add_test(NAME golden_compile
     COMMAND "${CMAKE_COMMAND}"
       "-DCXX=${CMAKE_CXX_COMPILER}"
       "-DRUNTIME_INCLUDE=${async_project_SOURCE_DIR}/runtime/include"
       "-DGOLDEN_DIR=${async_project_SOURCE_DIR}/transpiler/tests/golden"
       -P "${async_project_SOURCE_DIR}/cmake/check_golden_compile.cmake")
   ```

4. **`Makefile`**: in `test`, after the `golden_tests` line, add
   ```make
   	@for f in transpiler/tests/golden/*.expected.cpp; do \
   	  echo "golden-compile $$f"; \
   	  $(CXX) -std=c++20 -fsyntax-only $(RUNTIME_INC) $$f || exit 1; \
   	done
   ```

5. **README** "Building this repo": one sentence saying golden expected
   outputs must compile against `runtime/include` (`golden_compile`), so
   fixtures must declare whatever they await, normally as an `async`
   function in the fixture.

### Invariants

- **transpiler/runtime independence.** Neither `transpiler/` nor `runtime/`
  learns about the other. The join is in `examples/CMakeLists.txt` and the
  Makefile, which already join them, and the script receives paths as
  arguments.
- **Makefile/CMake parity.** Both get the check (steps 3 and 4).
- **Fail loudly.** A missing fixture directory or any non-compiling
  fixture fails the run, and the message names the fixture.

## Acceptance criteria

- [ ] With only steps 2–4 applied (old fixtures), `ctest --test-dir build -R golden_compile`
      **fails** and its output names both `nested_lambda.expected.cpp`
      (`'fetch' was not declared`) and `simple_fn.expected.cpp`
      (`awaitable type 'int'`). Record this in the Log; it is the test
      that fails without the fixture fix.
- [ ] With step 1 applied: `golden_tests` and `golden_compile` pass; the
      fixtures match the Blueprint text byte for byte. [evidence: transpiler/tests/golden/simple_fn.expected.cpp, transpiler/tests/golden/nested_lambda.expected.cpp]
- [ ] `cmake -DCXX=g++ -DRUNTIME_INCLUDE=runtime/include -DGOLDEN_DIR=/nonexistent -P cmake/check_golden_compile.cmake`
      exits non-zero with "no golden fixtures found". [evidence: cmake/check_golden_compile.cmake]
- [ ] `make BUILD=build-make test` prints one `golden-compile …` line per
      fixture. Breaking a fixture (e.g. deleting the `fetch` line from the
      expected file) makes it fail. [evidence: Makefile]
- [ ] `golden_compile` is registered in `examples/CMakeLists.txt` and runs
      in both `verify.sh full` and `verify.sh asan` (ctest lists it). [evidence: examples/CMakeLists.txt]
- [ ] README sentence added (step 5).
- [ ] `verify.sh all` passes.
